Demo runbook: Isa, Sprint 3 presentation

Second Star Collective · Willis Pearson, Eliyas Eshta, Matthew Brady · 15 minutes over Microsoft Teams. Team only until the presentation.

Runbook PatternIsa live demo · Sprint 3
Setup
Run the demo setup script, start Isa on the demo laptop, set the demo date to July 3, 2026, and sign in once as chapter president Watanabe Kenji (day 3 of his term).
Happy Path
Ask Isa three rehearsed questions and open Show the work; walk through Kenji's first 90 days (Today note, who to call, calendar, succession notebook, save an answer); then open the team's dashboard.
Edge Case
Isa stops responding during the demo (the sign-in service or the AI model on the laptop stalls), or the Teams screen share drops.
Recovery Script
Pivot to the backup video and screenshots, and tell the same story aloud while a teammate restarts the service. Rejoin the live demo only if it is back within a minute.

Setup, step by step (30 minutes before)

  1. Plug in the demo laptop, close other apps, and turn off notifications.
  2. With Isa stopped, run python onboarding\prepare_demo.py. It clears earlier rehearsals and puts back what Sato Yumiko left in the notebook, so every run starts the same way. Wait for "Ready."
  3. Start Docker Desktop and the sign-in service (start-keycloak.bat), then Isa (start-isa.bat).
  4. On the Config page, check the demo date is July 3, 2026.
  5. Sign in as Watanabe Kenji. His account also opens the Dev Dashboard, so nobody signs out during the demo.
  6. Warm up: ask each rehearsed question once, open the Today window, the notebook and the dashboard once, then run the setup script again only if the warm-up saved anything.
  7. Open the backup video and the screenshots folder in a second window, ready to share.
  8. Join Teams, share the browser window, and have a teammate confirm the text is readable.

Edge cases and recovery

If this happensSayDo
Isa shows "The sign-in service isn't reachable", or asks us to sign in again "While that reconnects, here is the same moment from our rehearsal." Presenter switches to the backup video or screenshots. A teammate checks Docker Desktop is running and runs start-keycloak.bat. If Isa restarted, check the demo date before going back.
An answer takes longer than about 15 seconds "Isa searches first and only asks the AI model when search alone isn't enough, and that step runs on this laptop." Keep talking through Show the work. If nothing comes, show the screenshot of that answer and go to the next part.
An answer differs from the rehearsed one "Let's look at how she got there." Open Show the work, read the steps as they are, and move on. Don't ask again and don't type an unrehearsed question.
A screen shows leftovers from a rehearsal (a step already done, a second saved answer) Nothing: carry on with the story. Prevent it: run the setup script before every run. It can't be run while Isa is running.
The Teams screen share or the internet drops "Isa runs entirely on this laptop, so she is still working; it's our call that dropped." A teammate takes over sharing with the backup video while the presenter rejoins (phone hotspot as a spare connection).
The demo laptop itself fails "We'll show you the recording of this exact walkthrough." A teammate plays the backup video from their own computer and the presenter narrates over it.

Recovery rules

  • One try, then pivot. Never debug on screen.
  • The story doesn't change: narrate the same moments over the video or screenshots.
  • Decide beforehand who shares the backup and who restarts the service.
  • Go back to live only if Isa is ready within about a minute; otherwise finish that section on the backup.
  • Spanish and Amharic stay out of the live demo; no audio is played over Teams.
